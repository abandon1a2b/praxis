在三个受控、只读代码分析样例中，修正后的 Praxis 原生 Pi 路径与 Codex 均通过：跨文件契约缺陷、超长行后的正常调查、无缺陷代码。此次结果支持继续使用 Pi 原生会话，不能推导整个产品已与 Codex 或 OpenCode 等价。

## 条件与复现

- Pi SDK：`@earendil-works/pi-coding-agent@1.1.0`；Codex：`codex-cli 0.162.0-alpha.2`。
- 同一网关、`gpt-6.1-sol`、low 推理、同一源码和用户任务；每个调用 180 秒上限。
- Pi 使用原生 read/grep/find/ls，启用压缩和有限重试。Codex exec 使用 read-only sandbox；其内置系统提示词和工具实现不同，Codex 可以执行只读命令。
- 每个样例每个 Harness 仅一次有效执行，顺序为 Pi 后 Codex；延迟受网络、缓存、服务负载和冷启动影响，不能据此宣称 Pi 更快。
- 输出记录包含工具事件和模型 usage。两边 usage 口径与缓存不同，网关不提供可信费用，本次不比较费用或以 Token 数量推断效率。
- OpenCode 已在本机发现（1.2.15），本轮没有调用；不作其性能结论。

运行 `npm run compare:harnesses` 重建全部样例并执行两边。可用 `npm run compare:harnesses -- clean-contract` 单独运行一个样例。脚本使用本机 Pi 的 local-gpt 配置与 Codex 凭据，不写凭据到输出；Codex 对照网关从 Pi 的模型配置读取，不绑定公司服务。可通过 `PRAXIS_COMPARE_PROVIDER` 和 `PRAXIS_COMPARE_MODEL` 指定 Responses 模型；Codex 凭据须有相同服务的权限。原始响应、会话、工具日志与 results.json 保存在脚本打印的系统临时目录。

## 失败记录与改进

首轮 Pi 未启用已注册工具，零工具调用后输出空问题；修正启用列表后正常探索。首次两边还曾在文件 id 前添加工作目录名，发现真实缺陷但未通过输出契约。任务明确相对路径与样例 id 后两边通过。

最初“无缺陷”样例把合法输入定义为任意有限非负价格，实际上 Number.MAX_VALUE 乘 100 会溢出，两边均指出这个真实缺陷。该样例不适合作为误报判定依据，已将合法输入明确为整数美元 0–1,000,000 和整数数量 1–1,000 后重跑两边；此前失败仍保留。

默认控制服务已切换为一个任务一个持久 Pi 会话，按需读代码，不强制字符分批。原生工具处理超长行时可能截断，但不会导致上层预处理失败。读取记录如实展示，不等同于全量语义覆盖。
