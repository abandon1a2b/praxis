# 检查计划、复核与恢复

## 目标与约束

控制层拥有检查范围与进度，Harness 只能执行指定阶段和提出候选问题。每次运行独立记录；相同配置及源码快照可接续工作。保持原生只读工具，不给模型修改配置或业务代码的能力。

## 已验证问题与先前方案

最初分批文本审查缺少跨模块探索；随后单次原生 Agent 探索改善工具访问，但一次 JSON 输出不能证明业务全量覆盖，超时后下一运行从头探索。此前实现见 5587f6d、caf9e29 及 native-agent-integration.md。读取事件只代表访问，不证明语义检查完整，这是已验证的接口限制。

## 当前方式

早期 0f59604 将目录分批，但仍要求先由模型理解整个仓库，并重复读取已提供的源码。GooseForum 首次实际运行纳入 1,226 个文件、140 批次；结构理解在 180 秒后超时，完成批次为零，读取事件 21 条。这验证了全仓自由探索作为前置步骤不可控，目录和字符数也不是业务边界。

当前 PLAN_VERSION=2：范围清单由控制层确定性生成，不消耗模型探索预算。topics 配置专题、跨前后端路径规则和判定标准，重叠文件归首个专题；专题优先，未命中文件保留补充检查。范围按字符预算拆分，保留长行列片段。模型直接检查编号源码，只探索必要依赖，不要求为生成读取记录重复读取。每阶段默认 60 秒，工具层最多允许 8 次探索，整轮仍受总时限约束。跨模块检查按专题分别持久化，不再一次探索整仓。

路径规则提供的是用户定义的业务线索，不能宣称自动理解了业务架构。工具预算只限制实际工具执行，模型可能继续提出被拒绝的调用，阶段时限仍是最终停止边界。全文语义覆盖不能由读取事件或 JSON 声明证明。

单批错误保存为 failed 后继续其他批次，未完成范围使运行保持失败而非宣称完成。后续运行优先处理尚未尝试的 pending 范围，再重试失败范围，避免一个难以处理的单元长期阻塞整仓。全局取消仍立即停止。

检查计划带版本，缓存键包含执行配置及源码内容，不依赖 Git dirty 标志。阶段完成时原子写入 checkpoint，失败只重试未完成阶段。工作区每次重新构造、结束后删除，缓存不保存源码。全局单执行约束保障 checkpoint 无并发写入。改变模型、目标、范围或源码会失效；升级执行协议需升级 PLAN_VERSION。

候选问题保留原文定位校验，另起模型会话挑战问题，记录 confirmed/rejected/needs-context。confirmed 只表示静态模型复核支持，未执行复现测试；不能宣称独立验证或运行时确认。

## 验证与残留风险

tests/review-plan.test.js 验证计划范围、失败后跨运行接续、问题状态保留和源码变更失效；native-review.test.js 验证原文及只读边界；web.spec.ts 验证计划展开及复核标签。相关实现为 src/agent-review.js、src/review-plan.js。

2026-10-12 GooseForum 重跑（c98d2082-0e25-4f39-a4da-f85f89d52dfa）：保留 1,226 文件全量范围，认证会话专题优先，字符预算 12,000，单阶段 60 秒、整轮 180 秒。完成 3 / 493 批次后触及整轮时限，暂无候选问题。证明可以跳过全仓探索直接推进并保存进度，不证明覆盖充分或缺陷检出准确率。较小批次提高局部可完成性，但全量耗时仍很长，需要继续评估预算与审查深度。

路径规则不是语义模块分析；跨模块探索及静态复核仍依赖模型。极大专题的文件清单和候选集合尚需分页或分层归并。单运行总时限可能不足以完成阶段，下一次触发续跑；单阶段持续超时需要更细分阶段。缓存无自动过期、清理和强制复查。上层目录及同账号访问仍不是 OS 沙箱。专题目前由 HTTP API 配置，页面编辑保留字段，但暂无专门专题编辑器。

从零重构应先定义覆盖证据层次、阶段预算、内容寻址缓存协议、模型复核和实际复现的区别，以及恢复与原运行记录的关系。回归需覆盖空输出、无读取、错误引用、长行截断、阶段取消、源码变化、缓存损坏和并发控制，避免把输出成功等同于目标达成。
