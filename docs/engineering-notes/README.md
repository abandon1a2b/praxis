# 工程难点记录

收集因实现缺陷、技术选型限制或架构问题而反复返工、难以稳定解决的专题，为未来从零重构提供提前识别难点的依据。普通视觉调整不纳入；前端交互和状态逻辑问题可以纳入。

每个专题使用独立 Markdown 文件，在发现反复返工时开始记录，随排查、修复和验证持续更新。

## 专题索引

- [代码检查分批边界](code-review-batching.md)：长行、字符预算、原始位置、Unicode 与缓存兼容问题。
- [原生 Agent 接入边界](native-agent-integration.md)：工具启用、跨程序输出契约和原生执行能力验证。
- [长轨迹索引与虚拟化](trajectory-index-and-virtualization.md)：增量字节游标、配对更新、源文件代次、动态行高度和阅读锚点。

## 记录内容

- 功能目标、运行环境和必要约束。
- 问题表现、触发条件与复现步骤。
- 根因及证据，区分已验证结论与待验证假设。
- 尝试过的方案、失败原因和选型取舍。
- 当前解决方式、验证结果及相关代码、测试和 commit。
- 未解决的问题与残留风险。
- 从零重构时应提前考虑的边界、选型条件和回归用例。

记录重点是为什么难、哪些方法不成立，以及如何验证解决方案，而不是重复执行日志或要求未来沿用当前实现。不要记录凭据或其他敏感信息。
