# 长轨迹：索引与虚拟化

原实现每次查询扫描并解析整份日志，加载历史后将所有行挂到 DOM。分页限制返回量但不减少服务端扫描，也不减少已加载行的渲染。需要同时改变数据读取和页面渲染，不能用另一个固定窗口掩盖问题。

## 当前方案

复用 TanStack Virtual 的动态测量、稳定行键和可见窗口；保存展开状态与加载前的阅读锚点。React 19 使用 useFlushSync=false，避免生命周期内同步刷新警告。顶部追加历史时保持原位置，跟随尾部仅在用户仍位于底部时启用。

SQLite 记录源文件身份、索引格式、已提交字节游标、64 字节锚点、用户轮次和模型步骤；投影按来源与原始序号索引。每个完整分块的投影与游标在同一事务提交，不完整行不推进游标。工具结束更新原调用行；文件替换、截断、原位修改尾部或格式变化时重建并切换来源代次。日志约定仅追加；任意中段原位修改不是受支持的写入方式，不能用局部锚点检测所有这样的修改。

失败事务保留此前已提交的分块，不清空正确前缀；重启从 SQLite 游标恢复。原日志暂不可读时仍可查询已建立的投影，原始全文和会话恢复仍需要源文件。

追加指令的接受记录和进入原生会话的用户消息是不同事实，明确保留接受记录，不通过全文相同猜测它们是否为同一事件。记忆注入也独立记录来源 id。索引不替代 Pi 模型上下文，不保存内部思维链。

## 验证及重构注意事项

测试覆盖分块提交、追加补齐工具结果、半行及 UTF-8、跨进程重启、源文件替换、10,000 条分页，以及 500 条 UI 的挂载上限、展开状态和前缀加载锚点。重复查询的“零新增正文读取”不等于零 I/O：仍执行文件 stat 和 64 字节锚点校验。

首次索引是 O(日志大小)，OFFSET 深分页仍有数据库遍历成本。后续更大规模应采用有代次的 keyset 游标和后台索引，不能丢弃历史或伪造步骤。长会话的上下文压缩与观察记忆仍是独立职责。
