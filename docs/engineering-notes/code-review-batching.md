# 代码检查分批边界

## 目标与约束

在固定字符预算下覆盖配置范围的全部代码，保留原始文件位置和可校验的证据。字符及列位置按 JavaScript UTF-16 长度计数。预算目前仅统计源码内容，不包括提示词、文件清单和 JSON 包装，不等同于 Token 或费用预算。

## 已验证的问题

- 初始分批按行处理，单行超过上限便抛错，导致整个业务在调用模型前失败。真实文件中出现 218,825 字符的一行，40,000 字符预算无法容纳；提高配置上限也不能可靠解决任意长行。
- 早期长度累计对末行多算了一个换行，恰好达到上限的单行产生超限批次。该问题已在 `ccdaa40` 修复。
- 对源文件重新插入换行会改变行号与代码语义；直接截断或跳过长行会丢失检查覆盖，均不作为解决方案。

## 当前实现与验证

普通行仍按原始行边界分批。超长行拆为受预算约束的片段，每段保留原始行号、起止列，不改源文件；列为从 1 开始的闭区间。UTF-16 代理对不在中间切开。报告展示分片列范围，提示词明确片段边界不能当作语法错误。

分批格式版本纳入缓存键，算法变更后不沿用旧批次下标。测试见 `tests/review.test.js`：长行完整重组、后续行号、批次上限、证据校验和 Unicode 边界；实现见 `src/review.js`、`src/pi-review.js`。

## 重构时需提前考虑

字符分片能保留内容，但不能保证跨片段的语义分析完整。压缩、生成或编码内容需要进一步考虑语法感知分片和上下文关联，并明确覆盖含义。提示词总大小、Token 预算、全局时限及扫描阶段取消仍需单独设计。跨片段的证据目前不能作为单条局部证据通过校验。
