# 只读巡检与观察记忆

第一版以可直接测量的检查验证长期运行和存储，不自动修改业务代码或生成未经验证的“经验”。支持 HTTP 状态与 Git 工作区检查。

## 使用

页面侧栏进入“巡检与记忆”，新建检查项，设置记忆范围、目标、正常条件、超时和间隔。定时巡检默认关闭；手动“立即巡检”会保存真实观察。HTTP 正常只表示本次返回码符合配置，不能泛化为整个业务健康。Git 正常只表示本次工作区干净。

接口通过 `GET /api/docs` 获取实时 schema：

- `GET/POST /api/inspections`：读取、创建及版本化更新配置。
- `POST /api/inspections/{checkId}/run`：等待单次测量完成，返回观察记录。
- `GET /api/memory?scope=...&q=...`：SQLite FTS5 关键词检索观察，默认最近 50 条，最多 200 条。
- `GET /api/incidents?scope=...`：查看首次发现、最近出现、重复次数、恢复及配置变更历史。
- `GET /api/observations/{id}`：读取不可变观察证据和当时的配置快照。

列表和任务上下文中的证据字符串最多预览 4,096 字符，明确标记截断；通过单条 observations 接口读取完整已保存证据。这样大工作区状态不会让记忆列表或模型初始上下文无限膨胀。FTS 仍索引原始已保存文本。

创建通用 Pi 任务时可选 `memoryScope`，带入该范围最近 5 条观察，包含 observationId、时间、检查版本、状态、概要和证据；原任务目标不变。任务事件及会话轨迹保留注入的来源引用。未指定范围时不自动读取记忆。历史状态可能过期，failed 表示检查未能确定状态，不能当作目标异常或恢复。

## 测量边界

HTTP 只发 GET，不自动跟随重定向，不支持嵌入 URL 的用户名密码。记录返回码、期望码、耗时和最多 8 KiB 响应正文，超出时标记截断。Git 使用固定的 rev-parse 和 status 命令，不提供任意 shell，并关闭可选锁与 fsmonitor。检查有 1–60 秒总超时。

这些检查与 Pi 任务、代码检查共用单执行上限。启用配置后首个检查在一个间隔后运行；停机期间不补造观察，重启后到期检查运行一次。尚未形成观察的执行若被硬终止，不声称已有结果。检查服务的正常退出会取消活跃测量并记录检查失败。

## 存储与状态

配置、观察、异常事件和 FTS 索引使用现有 SQLite。每次测量独立记录，不覆盖历史。异常第一次出现建立事件，重复出现增加次数；只有实际正常测量才关闭事件。网络或工具检查失败不会关闭异常。配置更新使旧版本活跃事件标记为 superseded，而不是 recovered；新版本独立判断。

记忆记录是测量事实，不是模型生成的结论。检索是关键词检索，非向量语义检索；包含汉字的查询使用范围内子串匹配，避免 SQLite 默认分词无法检索“本地接口”中的“接口”。其他查询使用 FTS5。当前不自动提炼策略、不自动修复、不通知外部人员。后续可扩展指标、验证过的结论和保留策略，但必须保留来源、适用条件和时间。
